Set up manually
Microsoft 365 mail, sign-in off (#384)
Shown after a DNS MX lookup finds Microsoft 365 (#384) when Microsoft sign-in is not set up in this build. Same screen and timing as the typed address: after Continue, cleared on edit, no password is asked. One string, {domain} filled in. The footer keeps “Change address”; “Set up manually” now stays visible in the column under the card, because the lookup can be wrong and manual setup is not refused for these domains. The ISPDB note on the normal email step now reads: “To find your mail servers, Envio asks the Thunderbird configuration database, your mail provider and the DNS records of your domain. Only the part of your address after the @ is sent.” It is hidden in this frame.

Set up manually
Microsoft 365 mail, sign-in on (#384)
Shown after Continue when a DNS MX lookup finds Microsoft 365 (#384) and Microsoft sign-in is set up; cleared on edit. The footer holds one button, the primary Sign in with Microsoft (Enter does the same). Under the card, in the column, sit “Change address” (outlined; clears the card and puts the cursor in the field) and “Set up manually”. “Set up manually” stays because DNS is unauthenticated, so a domain can look like Microsoft 365 without being one, and manual setup is not refused for these domains. The counter stays “Step 2 of 4”. A cancelled or declined browser step returns here with the card. The ISPDB note on the normal email step now reads: “To find your mail servers, Envio asks the Thunderbird configuration database, your mail provider and the DNS records of your domain. Only the part of your address after the @ is sent.” It is hidden in this frame.
