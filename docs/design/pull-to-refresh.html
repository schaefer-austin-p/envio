Notes

Behaviour

  • Only on the message list, with the list scrolled to the top and dragged down. No swipe actions on rows. The gesture and its 80 px threshold are the existing one (onDragEnded, contentY < -gu(10)), now a single shared value.
  • The indicator sits in the space the pull opens above the first row. It is part of the list (it moves with it) and never overlaps the tabs.
  • Release below the threshold: the list springs back, nothing is requested. Release past it: one refresh("") (all accounts), the list settles at 56 px (7 gu) with the busy indicator, then returns to 0.
  • Pulling back above the threshold before release disarms it ((b) goes back to (a)). Release is the only trigger; crossing the line alone never refreshes.

Sizes (px at 1x, 8 px = 1 gu)

  • Threshold: gu(10) = 80 px of overscroll, one shared value (a bindle property threshold; envio passes theme.gu(10), and its release check reads the same value). Frame (b) at 88 px is 11 gu.
  • Indicator row: 32 px glyph (4 gu), 10 px gap, 14 px text (Plex Mono in Carbon, Inter in Airmail). Row height follows the pull and is clipped by it, so the glyph is partly drawn on a short pull; busy rest height 48 px minimum (6 gu), 56 px (7 gu) as drawn.
  • Ring: 9 units radius on the 24-unit glyph, 2.5 stroke, progress arc = pull / threshold (capped at 100 %), starting at 12 o'clock; arrow 2 stroke. Armed: solid disc with the arrow flipped up. Busy: 30 % arc, one turn per second.
  • Busy rest height: 56 px (7 gu), held by the list header until the refresh ends, then eased to 0 (200 ms).

Colour tokens (no new colours)

  • Carbon light: ring track #DAD7CE, progress and disc #1E2A38, arrow on disc #F8F6F1, hint text #5A5D62, armed text #1E2A38 at weight 600, separator #E4E1D8. Carbon dark: #3A4049, #E8E5DE, #15181D, #A2A5AA, #E8E5DE, #2E343C.
  • Airmail light: track #DDD5C4, progress and disc #1F3A5F, arrow #FBF8F1, hint text #5D6A78, armed text #22303F weight 600, separator #EAE3D3. Airmail dark: #2C3747, #A9C1E3, #141C27, #A3AEBB, #ECE5D6, #2C3747.
  • The accent red is not used: it means unread and errors. These are the theme's existing ink, inverse, muted, text and separator roles; the board introduces no new colour. The dashed threshold line and its label in (a) and (b) are annotation only and are not drawn in the app.

Accessible names and text

  • The indicator is one element, role status, Accessible.name = the visible text: "Pull to refresh", "Release to refresh", "Refreshing" (all qsTr, domain envio.aps). The glyph is decorative and hidden.
  • Only the state change is announced (armed, busy), never the pull distance. Nothing is announced when the refresh ends; the list simply changes.
  • Screen-reader users have no drag gesture. No separate Refresh button is added in this step (open question 1).

Reduced motion

  • When the platform reports reduced motion (bindle exposes a writable property reducedMotion, default false where the platform offers no setting): the ring still follows the finger (direct manipulation), but the arrow flip is an instant swap, the busy ring does not spin (the static 30 % arc and the word "Refreshing" carry the state) and the settle back to 0 is instant.

No account online, empty list

  • All in-scope accounts offline or in a local error: the pull still arms and fires. Refresh is the retry-now for the connection, and the tab already shows the offline icon. The busy state ends as soon as the account reports not syncing again, after the 600 ms minimum.
  • Every in-scope account needs attention (sign-in failed, certificate pin, unsupported, broken): refresh cannot help, so no indicator is drawn, the list overshoots as plain bounce and release does nothing.
  • No accounts at all: no pull. Empty folder: the pull works the same; the empty state stays in place under the indicator, and the list must stay draggable when its content is shorter than the page (the brief has a test for it).
  • Scope: today the call is refresh("") (all accounts), kept for the unified list and for a single-account tab alike. A per-tab refresh is a possible follow-up (open question 2).

How the busy state ends

  • Core today: Event::AccountStatus (api/event.rs) and AccountStatus::Syncing exist, but they cannot drive this. The worker sets Syncing only while it works, Worker::report() emits only when the status after a step differs from the status before it (a normal Ready to Ready step emits nothing), and the bridge (Signal::Status to statusText) passes only text, with state_word mapping Syncing to "ok".
  • Minimum new event: Event::SyncActivity { active: bool }, sent when the worker's sync work (any account, queue of steps) goes from empty to non-empty and back, also on failure or offline. Bridged as a syncing bool property of EnvioCore, true while active.
  • QML: busy lasts from release until core.syncing is false, never shorter than 600 ms (a no-op refresh must not flash) and capped at 15 s (safety net if an event is lost). If the event is not built, the fallback is a fixed 1.2 s busy and then settle.
