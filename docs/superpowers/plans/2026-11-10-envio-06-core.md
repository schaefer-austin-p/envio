# Envio Plan 6: envio-core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `crates/envio-core`, the Qt-free core that Plan 7's cxx-qt glue calls: commands in, events out, on one worker thread that owns the store, the IMAP/SMTP sessions and the sync driver. It adds and removes accounts (autoconfig, the SRV confirmation, the self-signed prompt), keeps passwords in their own 0600 file, syncs (IDLE on the Inbox in the foreground, polling otherwise, every connection assumed dead after a resume), replays user actions after a 5 s Undo window, queues and sends mail through the Outbox without ever resending on its own, saves drafts within about 1 s, sorts every failure into the spec's kinds with translated text, keeps credentials out of logs, and survives a worker panic.

**Architecture:** `Core::start(config, sink)` spawns one supervisor thread; it builds a tokio current-thread runtime and runs the `Worker` under `catch_unwind`, restarting it after a panic (crash log written locally). Everything the worker touches (store, sessions, sync's `Schedule`) is created inside that thread and never crosses it, so no future needs `Send` (#39). The worker's loop `select!`s over the command channel, the per-account IDLE futures and one timer; work runs as `Step`s (folders, replay, send, file, one folder, one body) planned by pure functions in `worker/plan.rs`, one step at a time with commands handled between steps. Pure modules at the crate root (`problem`, `health`, `undo`, `compose`, `outbox`, `servers`) carry the decisions; `worker/` drives them. All user text is built in `src/text/` with gettext (`envio.aps`).

**Tech Stack:** Rust 1.94 (edition 2024); tokio 1.54 (`rt`, `time`, `sync`, `macros`; current-thread only); futures 0.3; secrecy 0.10 (`SecretString`, `secrecy::zeroize`); serde 1 / serde_json 1; log 0.4 (the facade async-imap and rustls already use; envio-core installs the only logger); gettext-rs 0.7 with `gettext-system` (glibc's libintl, the same catalogue `qt/main.cpp` binds); thiserror 2; tempfile 3 (tests). envio-sync, envio-net, envio-store and envio-mime from Plans 2 to 5. Stalwart v1.0.3 in Docker for `envio-e2e`.

**Spec:** `docs/superpowers/specs/2026-11-07-envio-design.md`, sections "Architecture", "Data flow and storage", "Passwords, certificates, privacy", "Error handling", "Testing and CI". Issues: #43, #42, #41, #40, #39, #37, #34, #27, #22, #21, #17, #14 (see "Issues" below).

## Global Constraints

- Workspace package values (`rust-version = "1.94"`, `edition = "2024"`, `GPL-3.0-only`); every crate has `[lints] workspace = true`.
- Dependencies point one way: core → sync → net, store, mime (core may also use net, store and mime directly). net, store and mime never depend on each other.
- The core is Qt-free. `unsafe_code = "forbid"` in the root workspace; `unsafe` only in `qt/`.
- One concept per module, files around 300 lines; logic kept out of I/O code (pure modules decide, `worker/` drives).
- Clippy: `clippy::all`, `cognitive_complexity` threshold 15, `too-many-arguments-threshold = 4` (`self` counts); CI uses `-D warnings`.
- One worker thread with a tokio **current-thread** runtime; `block_on` only, never `spawn` / `spawn_local` / `LocalSet`; net spawns nothing (#39).
- Passwords live only in `<data>/passwords.json` (mode 0600, written atomically), in memory only as `SecretString`; never in the database, `accounts.json`, logs, crash logs, events or `Debug` output.
- Never enable trace (or debug) for the `async_imap` and `imap_proto` log targets: they are capped at `Warn` whatever the global level, debug builds included (#37).
- Logs mask addresses and subjects (`mask::address`, `mask::subject`); account keys, folder ids and Outbox ids may be logged.
- TLS only; a changed pin stops the account and is never accepted on its own; a malformed stored pin stops the account, it is never dropped.
- Envio never resends on its own: only the user's Send again (after the Sent search came up empty) or Retry (after a refusal) puts an item back to `Queued`.
- Unsent work (Outbox, drafts, pending actions) lives outside SQLite and is saved within about 1 s (drafts: at most `DRAFT_SAVE_MS = 1_000` after the first unsaved change).
- Undo window `UNDO_MS = 5_000` (envio-sync's constant); retry backoff 1 s to 5 min with jitter (envio-sync's `backoff_ms`); poll / full-sync interval `POLL_MS = 300_000`.
- User-facing text is translated: `tr`/`tr_n` (gettext, domain `envio.aps`) called only in `crates/envio-core/src/text/`, with single-line plain `"…"` literals; run `cargo make pot` after changing strings. QML only shows the text events carry.
- Migrations are numbered and never edited after merge (this plan adds none).
- Single-crate integration tests in `crates/<crate>/tests/`; anything that needs two crates (and Stalwart) in `crates/envio-e2e`.
- `qt/` is its own workspace with its own `qt/Cargo.lock`: after adding core dependencies run `cargo update -p envio-core --manifest-path qt/Cargo.toml` and `cargo make app-docker`.
- `cargo make ci` must pass at every commit; tasks touching `envio-e2e` also run `cargo make e2e-it`.

## Decisions (where the spec leaves a gap)

1. **#39 is settled by the runtime, not a bound.** The worker builds its current-thread runtime and every session inside its own thread and only `block_on`s, so `MailServer` futures need no `Send`. envio-sync documents the contract; core asserts at compile time that only `Core` (the handle) is `Send + Sync`.
2. **Commands and events are plain enums** (`api/command.rs`, `api/event.rs`); events go to an `EventSink` the glue implements (Plan 7 queues them onto the Qt thread). Reads (folders, message pages, an opened message) are commands answered by events too, so the store has one owner.
3. **Work runs as steps**, one at a time, with commands handled between steps; IDLE futures for idle accounts are polled by the same `select!`. A long first sync of a folder delays commands until that folder's batch ends (risk noted).
4. **IDLE wakes sync only the Inbox**; a full run (every folder) happens at start, on resume, on Refresh and every `POLL_MS`. Servers without IDLE get the same full run every `POLL_MS`.
5. **Passwords file:** `{"version":1,"passwords":{"<account key>":"…"}}`. A file that can't be parsed is moved to `passwords.json.damaged` and Envio starts with none (the accounts show "Sign-in failed, update password"); it is never silently overwritten while readable.
6. **Account removal (#22, #42):** the user is asked first whenever `envio_sync::driver::unsent` is non-zero, with the counts; on confirm the account key goes into `<data>/removing.json` before anything is deleted, the account leaves `accounts.json`, then sync's `remove_account`, then its password. Startup finishes any removal listed there. Nothing is orphaned.
7. **Replay ceiling (#40):** only `Protocol` failures count toward a ceiling of 10; the action is then given up (marked done, the user told, its folder resynced). `Temporary` never gives up: offline is normal and the account backoff already caps at 5 min.
8. **Gettext extraction:** gettext 0.21 in the CI image has no Rust parser, so `update.sh` runs `xgettext --language=C` over `crates/envio-core/src/text/*.rs` only; a unit test keeps those files free of lifetimes and char literals (which confuse the C lexer).
9. **Logs and crash logs** go to `<cache>/logs/` (`envio.log`, rotated to `envio.log.1` at 1 MiB; `crash-<unix ms>.txt`); never uploaded.
10. **Disk full** stops downloads (folder and body steps) for every account; replay, send, filing and local writes go on; a folder step is tried again after `POLL_MS`. **A damaged cache** mid-session: the worker drops the `Db`, calls `open_or_rebuild`, says so in a notice and runs a full sync of every account.
11. **Drafts upload to the server's Drafts folder is deferred to Plan 7** (the store's `Draft` has no Message-ID yet); drafts are safe locally. Attachments are kept in a draft as file paths (Task 2 adds `Draft.attachments`) and read from those paths at Send.
13. **Body prefetch on Wi-Fi is deferred to Plan 7**: core can't tell Wi-Fi from mobile data without the platform; bodies download on open until then.
12. **The ISPDB privacy note** is a plain function (`text::setup::ispdb_note()`) the glue calls before `Detect`, so the wizard says it before the domain leaves the phone.

**Interfaces:**
- Consumes: `Schedule::{failed, failures, succeeded}`, `ErrorKind`, `Filed`, `Replayed` (Plan 5).
- Produces:
  - `pub enum Outcome { Done, Revert, Retry(ErrorKind), Stop(ErrorKind) }` (Retry now carries `Temporary`, `Protocol` or `Local`).
  - `pub const GIVE_UP_AFTER: u32 = 10;` and `pub fn give_up(kind: ErrorKind, failures_so_far: u32) -> bool` in `plan/replay.rs`.

**Invariants:**
- `give_up` is true only for `ErrorKind::Protocol` with `failures_so_far + 1 >= GIVE_UP_AFTER`; `Temporary` never gives up.

- `stopped` reports the real kind (`Protocol` vs `Temporary`), never `Temporary` for both.
- Every Message-ID search and `MoveRoute::CheckTarget` uses `search_id`'s trimmed id.
- In `file_sent`, a `Resolve` item whose Sent SELECT or Sent search is refused goes into `Filed::ask` (the user decides); `File` items keep going to `unfiled`. No path sets `Queued`.
- `server.rs` doc says the futures are deliberately not `Send`: core runs them on one current-thread runtime with `block_on` (#39).

**Tests:**

```rust
pub(crate) fn write_atomic(path: &Path, bytes: &[u8], mode: u32) -> io::Result<()> {
    let dir = path.parent().unwrap_or(Path::new("."));
    let name = path.file_name().unwrap_or_default().to_string_lossy();
    let tmp = dir.join(format!(".{name}.{}.tmp", std::process::id()));
    let _ = fs::remove_file(&tmp); // a stale temp from a crash
    let result = (|| {
        let mut f = OpenOptions::new().write(true).create_new(true).mode(mode).open(&tmp)?;
        f.write_all(bytes)?;
        f.sync_all()?;
        fs::rename(&tmp, path)?;
        File::open(dir)?.sync_all()
    })();
    if result.is_err() { let _ = fs::remove_file(&tmp); }
    result
}
```

```rust
pub fn decide(state: &SendState, decision: OutboxDecision, asked: bool) -> Result<Decided, NotNow> {
    use {OutboxDecision as D, SendState as S};
    match (state, decision) {
        (S::MayHaveBeenSent, D::SendAgain) if asked => Ok(Decided::SetState(S::Queued)),
        (S::MayHaveBeenSent, D::MoveToSent) if asked => Ok(Decided::SetState(S::Accepted)),
        (S::Failed { .. }, D::Retry) => Ok(Decided::SetState(S::Queued)),
        (S::Queued | S::Failed { .. }, D::Delete) => Ok(Decided::Remove),
        (S::MayHaveBeenSent, D::Delete) if asked => Ok(Decided::Remove),
        _ => Err(NotNow),
    }
}
```
