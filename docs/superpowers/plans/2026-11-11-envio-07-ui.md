# Envio Plan 7: UI for 0.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Envio usable on the phone: the QML screens of 0.1.0 (account wizard, unified inbox with account tabs, reader, compose, Outbox, search, settings) driven by envio-core through a thin cxx-qt glue, plus the core and store work only the UI needs and the must-fix issues of milestone 11.

**Architecture:** A new Qt-free crate `envio-ui` turns core events into list rows and model changes (insert, update, remove, reset) and keeps the UI's request bookkeeping (current list, cursor, selection, toasts), so that logic is unit-tested with `cargo test`. `qt/` wraps it: one `EnvioCore` QObject (invokables in, signals out) and four `QAbstractListModel`s whose rows come from `envio-ui`; the core's `EventSink` queues each event onto the Qt thread through `CxxQtThread`. QML pages take the core as a property, so qmltestrunner tests drive them with a QML mock. Drafts move out of the worker into a `DraftKeeper` thread inside `Core`, and account setup runs on its own thread, so a long network step no longer delays saving (#46).

**Tech Stack:** Rust 1.94 (edition 2024); cxx 1.0.205, cxx-qt / cxx-qt-lib 0.10.0 (exact pins, `qt/` workspace); Qt 5.15 / QML (Ubuntu Touch 24.04 framework `ubuntu-touch-24.04-1.x`); Lomiri.Components, Lomiri.Content (Content Hub), url-dispatcher, only inside `qml/platform/ut/`; qmltestrunner (offscreen) for QML tests; SQLite FTS5 (migration 0003); webpki-roots (bundled CA fallback, #31); fonts Inter, IBM Plex Mono, Lora (SIL OFL 1.1, bundled).

**Spec:** `docs/superpowers/specs/2026-11-07-envio-design.md`, sections "Scope / 0.1.0", "Architecture", "Passwords, certificates, privacy", "Error handling", "Testing and CI". Look: `docs/10-design.md`, `docs/design/*.html`, and the board inventory `.superpowers/sdd/2026-11-11-envio-07-ui/screens.md` (copied from the design canvas; `[OVR]` marks where `10-design.md` overrides a board). Issues: #46, #49, #50, #37, #33, #31, #29, #22, #20, #18, #15, #8, #5, #4, #3 (see "Issues").

## Global Constraints

- Workspace package values (`rust-version = "1.94"`, `edition = "2024"`, `GPL-3.0-only`); every root-workspace crate has `[lints] workspace = true`.
- Dependencies point one way: ui → core → sync → net, store, mime (core may use net, store, mime directly). net, store and mime never depend on each other. `qt/` depends on `envio-ui` and `envio-core` only.
- Logic in Rust; Qt and QML only for UI and platform APIs. `qt/` holds no logic: each invokable calls one `envio-ui`/`envio-core` function, each model reads rows `envio-ui` produced. `unsafe` only in `qt/`. The core and `envio-ui` are Qt-free.
- Lomiri, Suru, Lomiri.Content and url-dispatcher APIs only in `qml/platform/ut/`; pages use the wrappers in `qml/platform/`.
- One concept per module, files around 300 lines (QML pages too: split into components under `qml/components/` or a page's own folder).
- No swipe actions on list rows (Ubuntu Touch edge gestures). Long-press starts selection.
- User-facing text is translated: `qsTr()` in QML, `tr`/`tr_n` in `crates/envio-core/src/text/` only (domain `envio.aps`); run `cargo make pot` after changing strings. **QML never formats a count**: no `qsTr(…, …, n)` and no `%n`; counted text comes from Rust (`tr_n`) through the glue (#3). A CI grep enforces it (Task 10).
- Passwords: only `SecretString` in Rust; QML holds a password only in the field's text and passes it straight to `EnvioCore.connect`/`updatePassword`; the glue converts to `SecretString` at once and never logs or stores it. `TextField` for passwords uses `echoMode: TextInput.Password` and no `inputMethodHints` that enable prediction.
- Never enable trace (or debug) for the `async_imap` and `imap_proto` log targets (#37). Logs mask addresses and subjects (`mask::address`, `mask::subject`).
- Privacy: remote images blocked by default (allowed per message or per sender); a link shows its real address before it opens; the wizard says, before detecting, that only the domain goes to Thunderbird's ISPDB (`text::setup::ispdb_note()`).
- TLS only. A self-signed certificate is accepted only through the fingerprint dialog, whose primary (filled) button is **Cancel**. A changed pin is never accepted on its own.
- Envio never resends on its own (Outbox decisions only through `DecideOutbox`).
- Unsent work (Outbox, drafts, pending actions) lives outside SQLite and is saved within about 1 s (`DRAFT_SAVE_MS = 1_000`), including while the worker is busy in a network step and across a worker panic.
- Migrations are numbered and never edited after merge (this plan adds `0003`).
- Theme roles only: pages never hard-code a colour or font family; they read `Theme` (Task 10).
- Touch targets at least 44 px high (`10-design.md`); sizes in `units.gu`-scaled values through `Theme` (`Theme.gu(n)`).
- Single-crate integration tests in `crates/<crate>/tests/`; anything needing two crates (and Stalwart) in `crates/envio-e2e`. QML tests in `tests/qml/tst_*.qml`, run by `cargo make qml-test`.
- `qt/` is its own workspace with its own lock: after changing root-crate dependencies run `cargo update -p envio-core -p envio-ui --manifest-path qt/Cargo.toml`, then `cargo make app-docker`.
- `cargo make ci` passes at every commit; tasks touching `qt/`, `qml/`, `CMakeLists.txt` also run `cargo make app-docker` and `cargo make qml-test`; tasks touching `envio-e2e` run `cargo make e2e-it`.

## Decisions (where the spec leaves a gap)

1. **`envio-ui` holds the UI's state logic.** It is a plain Rust crate (`crates/envio-ui`, depends on envio-core): `Ui::apply(Event) -> Vec<Output>` where an output is a model change (`ModelChange { model, op }`) or a one-shot signal (`Signal`). It also maps UI calls to `Command`s (`Ui::open_list`, `Ui::more`, …) and remembers which list, cursor and selection are current, so stale answers (an old page arriving after a tab switch) are dropped in Rust, not QML. `qt/` mirrors outputs onto models and signals. Blast radius: trunk (it decides what mail shows on screen); CLAUDE.md is updated in Task 8.
2. **Drafts leave the worker (#46).** `Core` owns a `DraftKeeper` on its own thread (`envio-drafts`) that receives `DraftChanged`, `CloseCompose`, `Attach`, `AppActive(false)` and `Shutdown` directly from `Core::send`, throttles and saves (`Drafts` files). It survives a worker panic (it is outside the supervisor). The worker reaches it through a shared `Arc<DraftBook>` (a `Mutex` held only around a file write) for `Send` (flush, then delete after enqueue) and `StartCompose`. A draft's attachments are copied into `<data>/drafts/files/<draft id>/` on `Attach`, because Content Hub paths are transient (#18).
3. **Setup leaves the worker (#46).** `Detect` and the network probe of `Connect` (login to IMAP and SMTP, certificate check) run on a `envio-setup` thread with its own current-thread runtime; its result comes back into the worker's queue as an internal input. The worker's channel becomes `Input = Command(Stamped) | Setup(SetupDone)`. Plan 6's "block_on only, never spawn" still holds per thread: each thread `block_on`s its own runtime and no future crosses a thread.
4. **A folder step fetches at most `BATCHES_PER_STEP = 2` batches (100 messages)** and returns `Synced { more: true }`; the worker queues the same folder again ahead of other folders of that account, so commands run between parts. The sync state's `finish` is written only after the last part. A stalled connection still waits out its 60 s command timeout; with Decisions 2 and 3 that delays reads, not saving or setup.
5. **A store that won't open says so (#49).** After the first failure the worker emits `Event::StoreProblem { text }` (the app shows a full-page error with "Try again") and keeps retrying with backoff; drafts are safe in the keeper meanwhile. An account whose stored pin (or other field) is malformed loads as `Account { broken: Some(reason) }`; only that account is stopped (`AccountStatus::Broken`), the others sync.
6. **Roots (#31).** `envio_net::Roots::system()` keeps returning what it loaded; core's start uses `Roots::system_or_bundled()`, which falls back to `webpki-roots` when the system store is empty and records `RootsSource::{System, Bundled}`. The glue logs the source, the count and every load error at startup (#37 remainder). The trust prompt is never shown while the roots are empty (`Roots::is_empty()` → `SetupProblem(text::setup::no_roots())`).
7. **Lists use a keyset cursor (#20).** `Cursor { date: i64, id: MessageRowId }`, newest first: rows with `(date, id) < cursor`. A list is `ListRef::Folder(FolderId)` or `ListRef::Inboxes` (every account's Inbox, the unified inbox). Page size `PAGE = 50`. New mail does not shift the next page; `MessagesChanged` makes `envio-ui` reload the first page and merge.
8. **Unread counts** are one `GROUP BY folder_id` query over `flags & SEEN = 0`; `FolderRow.unread` is filled from it, and `AccountInfo.unread` is the Inbox count.
9. **Body search and addresses (#22).** Migration `0003` adds `bodies_fts(text)` (FTS5, rowid = message id) filled when a body is downloaded (the text part, or HTML stripped to text by envio-mime, first 64 KiB), deleted by trigger with its message; and `addresses(address TEXT PRIMARY KEY, name, last_seen, count)` filled from From/To/Cc of synced envelopes and of sent mail. Local search queries both FTS tables. Autocomplete merges `addresses` with saved contacts; the cache can be rebuilt, so `addresses` is a cache too, refilled by sync.
10. **User data files (outside the cache, atomic writes, `<data>/`):** `settings.json` (`Settings`), `contacts.json` (saved contacts: "Add sender to Contacts"). Allowed image senders live in `Settings.images_from`.
11. **Search on server** searches one folder (the list being viewed; Inbox for the unified inbox, per account) with `search_text`, then fetches envelopes for UIDs not cached and upserts them into the cache like synced rows (a later sync may drop rows outside the 30-day window; an open reader keeps its copy). Results come as `SearchResults { server: true }`.
12. **Counted text** comes from Rust: `text::count::{selected, results, waiting, unread_label}` (`tr_n`), exposed by `EnvioCore.countText(kind, n)`. The QML translator keeps no plural path; the CI grep makes that safe (#3).
13. **Dates:** `envio-ui` picks the bucket (`DateBucket::{Time, Weekday, DayMonth, Full}` from now, the row's date and the local UTC offset); QML formats the bucket with `Qt.locale()`.
14. **Deferred to the backlog (new issues, milestone 13):** uploading drafts to the server's Drafts folder (#18's second bullet; local drafts are safe), body prefetch on Wi-Fi and the "Attachments on mobile data" switch, the push relay row, a "Keep mail for" choice (fixed at 30 days and shown as text).
15. **Platform wiring:** `mailto:` through a url-dispatcher hook (`envio.url-dispatcher`: `[{"protocol": "mailto"}]`), read from `Qt.application.arguments` at start and from Lomiri's `UriHandler` while running (`platform/ut/UriSource.qml`). Content Hub: `platform/ut/ContentImport.qml` (pick files to attach) and `ContentExport.qml` (Open, Save, Share an attachment); AppArmor adds `content_exchange_source`. App state: `Qt.application.state` → `AppActive`.
16. **Config paths** come from Rust: `envio_core::paths::app_dirs(app_id) -> (cache, data)` from `XDG_CACHE_HOME` / `XDG_DATA_HOME` (defaults `~/.cache`, `~/.local/share`) plus the app id `envio.aps`, the folders confinement allows.

- Migration 0003 only adds (tables, triggers, index); it is tested from schema 0001 and 0002 like the others. `bodies_fts` rows are deleted by an `AFTER DELETE ON messages` trigger; `addresses` is independent of messages.
- `suggest("")` returns nothing; FTS queries are built with the existing safe quoting (no raw user text in `MATCH`).

### Task 3: envio-net and envio-sync: bundled roots fallback; a folder synced in parts (#31, #46)
