# Envio Plan: Two-pane layout on tablets and desktop (#192)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At a window width of 90 gu or more, the list and the reader (or compose) sit side by side; narrower windows keep today's page stack. The switch is live and loses nothing. Mouse and keyboard get hover, a right-click menu and shortcuts.

**Design:** `docs/design/carbon-two-pane.html` (frames 1 to 9; the notes under each frame are part of the spec). `docs/10-design.md` has the new `hover` role.

**Architecture:** Selection, the open message and paging stay in `envio-ui`; QML only arranges panes. `AppShell` gets a plain `wide` flag and a `Row` of the list and a `Loader` (reader, compose or empty). No `AdaptivePageLayout`. The reader page and the compose page are single items that are reparented between the `StackView` and the pane, never recreated.

**Tech Stack:** Rust (`envio-ui`, `envio-core`), cxx-qt in `qt/`, Qt 5.15 / QtQuick 2.15, `qmltestrunner` offscreen.

## Global Constraints

From `CLAUDE.md`, verbatim where quoted:

- "Logic in Rust, Qt and QML only for UI and platform APIs. The core is Qt-free; `unsafe` only in `qt/`."
- "No swipe actions on list rows (Ubuntu Touch edge gestures)." Mouse and keyboard only add hover, the right-click menu and shortcuts.
- "User-facing text is translated: `qsTr()` in QML, gettext in Rust, domain `envio.aps`. Run `cargo make pot` after changing strings." Key names (Enter, Del, Ctrl, Esc) are translatable; the empty-state hint is `qsTr("Or press %1 to write one")` with the key chip as the argument. Reuse `qsTr("Move to folder")` from `SelectionBar.qml`.
- "Unsent work (Outbox, drafts, pending actions) lives outside the SQLite cache and is saved within about 1 s."
- Lomiri and Suru APIs only in `qml/platform/ut/`; everything here is plain QtQuick.
- Test mail and screenshots use synthetic accounts and `example.org` / `envio.test` only.
- `cargo make ci` passes at every commit; QML tasks also `cargo make qml-test`; tasks touching `qt/` or `qml/` also `cargo make app-docker`.
- Blast radius: `envio-ui`, `envio-core`, `qt/`, `qml/Main.qml` and `Theme.qml` are trunk (full review); other QML is leaf.

## Decisions (from the design review)

1. **The open row is not multi-select.** `envio-ui` has an "open message id"; rows have an `open` role. The open row shows the selected fill plus a 3 px accent bar. Multi-select checkmarks and the selection bar stay as on the phone; in wide mode the right pane keeps showing the open message while rows are checked.
2. **Reader and compose survive a width change by reparenting.** No page is created or destroyed, so nothing reopens. Scroll is stored as a fraction (or anchor). Moving or destroying a page never calls `closeCompose`; this rule applies to reparenting on a width change only (a row click during compose is not a layout move, see 3). Cursor and quote fold are best effort.
3. **Clicking another row while compose is in the pane** closes the compose the way `leave()` does, keeping the draft in Drafts: `ComposePage.flush()`, then `commitAll()` and `core.closeCompose(compose, false)` (which saves any pending draft at once), then `paneCompose` clears, the clicked message opens in the reader, and a new toast `qsTr("Draft saved")` shows. With compose in the pane no row is open; afterwards the open row marks the message in the reader.
4. **Layout:** `wide` is `width >= theme.gu(90)` with a hysteresis of 4 gu (switch to wide at 90 gu, back to narrow only below 86 gu; drawn on board frame 6). AppShell keeps the compose that is in the pane in its own property `paneCompose` (an id, 0 for none): set from `composeOpened`, cleared when the compose closes. `core` has no compose id of its own.
5. Hover role in all four palettes: Carbon light `#F3F1EA`, Carbon dark `#1B2027`, Airmail light `#F7F2E8`, Airmail dark `#18222E` (each about 40% from ground toward selected); selected stays as is.
6. Scope: Search, Outbox, Settings and Accounts are full-window pages over both panes; toasts are centred at the bottom of the window; a folder change clears the open message; Close (X) on compose shows the existing Discard or Save draft sheet; Delete, Esc and "?" do nothing while a text field has focus; the shortcuts dialog gets a new Settings row.
7. Units: reader measure 80 gu; image `bodyWidth = min(pane width minus margins, 80 gu)`; Reply and Forward 20 gu wide; breakpoint `>=` 90 gu; the third column (drawer) from about 180 gu needs an inline mode of `FoldersDrawer`.
8. Airmail: one `AirmailFrame` around the whole window, a plain hairline between panes.
